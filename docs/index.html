1. Персональная лицензия бойца

Формат: KAPT-XXXX-XXXX-XXXX
Привязывается к бойцу на 30 суток. Боец может быть переведен в другую роту, взвод или на другой склад — его оплаченная лицензия остается с ним на его устройстве.

2. Ключ склада подразделения

Формат: kapt_xxxxxx
Общий код синхронизации имущества роты. Все бойцы одного подразделения (командир, старшина, начсклада, пулеметчики) вводят этот код для работы с единым общим складом.

Командный склад

Как организовать работу роты:

  1. Старшина или командир роты создает склад и нажимает «Сформировать ключ роты» (например, kapt_59e13b).
  2. Каждый боец подразделения оплачивает или получает свой персональный ключ (KAPT-XXXX-XXXX-XXXX) на сайте или в приложении.
  3. Бойцы вводят общий ключ роты в разделе «Синхронизация подразделения» на своих смартфонах.
  4. Результат: Вся рота видит единые актуальные остатки боеприпасов, бронежилетов, аптечек и заявок без взаимных блокировок!
Архитектура связи

Механизм облачной синхронизации и Ключ подразделения

Ядро системы — это уникальный Ключ подразделения. Он работает как пароль от изолированного облачного контейнера, в котором хранятся данные только вашей роты, взвода или батальона.

1. Создание ключа (Командир)

При первой регистрации программа автоматически генерирует уникальный 6-значный код (например, kapt_b5e9f1). Командир может заменить его на свой (например, ROTA_1_VKS). Этот ключ навсегда привязывается к профилю в настройках.

2. Подключение бойцов

Второй боец при установке приложения выбирает вкладку «Войти в подразделение» и вписывает точно такой же ключ. Программа валидирует ключ и связывает устройства в единую защищенную сеть.

3. Облачный хаб (Firebase)

При наличии связи приложение обращается к базе данных Google Firebase по вашему ключу. Оно скачивает измененные остатки/заявки от других бойцов и загружает ваши проведенные операции. Вся группа видит общую картину.

4. Локальный Offline-режим

Если интернета нет из-за работы РЭБ или нахождения в бункере, система переключается на внутреннюю базу SQLite (Room DB). Вы продолжаете выдавать имущество, а программа выгрузит данные в облако, как только появится сеть.

Архитектура безопасности (OPSEC)

Безопасность фронтового уровня

Техническое обоснование безопасности использования программного комплекса «Каптёрка ПРО» в условиях активного радиоэлектронного подавления и перехвата (РЭБ / РЭР). Продукт спроектирован с учетом требований информационной безопасности (ИБ) для работы на линии боевого соприкосновения.

🚫 1. Нулевая телеметрия и геолокация

Приложение не запрашивает и не использует API геолокации Android (GPS/ГЛОНАСС). В манифесте полностью отсутствуют разрешения на доступ к геолокации. Сторонние аналитические трекеры исключены из сборки.

🔒 2. Изолированная локальная БД

Весь массив учетных данных (остатки БК, экипировка, списки бойцов) сохраняется исключительно в изолированном хранилище устройства (App-Specific Storage) в формате SQLite (Room). Архитектура построена на парадигме 100% Offline-First.

📴 3. Режим радиотишины (No Push)

Синхронизация складов роты происходит исключительно по ручной команде пользователя. В приложении нет фоновых демонов и push-уведомлений, излучающих в радиоэфир.

🔑 4. Оффлайн-Активация (Air-Gapped)

Активация военного ключа (KAPT) производится через криптографическую проверку контрольной суммы непосредственно на устройстве без обязательного соединения с биллингом.

Механизм облачной синхронизации

Единая сеть роты и ключ подразделения (kapt_xxxxxx)

Ядро системы — это уникальный Ключ подразделения. Он работает как пароль от изолированного защищенного контейнера данных, в котором хранятся остатки имущества только вашей роты, взвода или батальона.

1. Создание ключа (Командир)

При первой регистрации программа автоматически генерирует уникальный 6-значный код (например, kapt_b5e9f1). Командир может заменить его на свой (например, ROTA_1_VKS). Этот ключ навсегда привязывается к профилю в настройках.

2. Подключение бойцов

Второй боец при установке приложения выбирает вкладку «Войти в подразделение» и вписывает точно такой же ключ. Программа валидирует ключ и связывает устройства в единую защищенную сеть.

3. Облачный хаб (Firebase)

При наличии связи приложение обращается к базе данных Google Firebase по вашему ключу. Оно скачивает измененные остатки/заявки от других бойцов и загружает ваши проведенные операции. Вся группа видит общую картину.

4. Локальный Offline-режим

Если интернета нет из-за работы РЭБ или нахождения в бункере, система переключается на внутреннюю базу SQLite (Room DB). Вы продолжаете выдавать имущество, а программа выгрузит данные в облако, как только появится сеть.

Архитектура безопасности (OPSEC)

Безопасность фронтового уровня в условиях РЭБ/РЭР

Техническое обоснование безопасности использования программного комплекса «Каптёрка ПРО» в условиях активного радиоэлектронного подавления и перехвата (РЭБ / РЭР). Продукт спроектирован с учетом требований информационной безопасности (ИБ) для работы на линии боевого соприкосновения.

🚫 1. Нулевая телеметрия и геолокация

Приложение не запрашивает и не использует API геолокации Android (GPS/ГЛОНАСС/Network). В манифесте полностью отсутствуют разрешения ACCESS_FINE_LOCATION и ACCESS_COARSE_LOCATION. Сторонние аналитические трекеры исключены из сборки.

🔒 2. Изолированная локальная БД

Весь массив учетных данных (остатки БК, экипировка, списки бойцов) сохраняется исключительно в изолированном хранилище устройства (App-Specific Storage) в формате SQLite (Jetpack Room). Файлы недоступны другим приложениям без Root-прав.

📴 3. Режим радиотишины (No Push)

Синхронизация складов роты происходит исключительно по ручной инициативе пользователя. В приложении нет фоновых сервисов и push-уведомлений, излучающих в радиоэфир.

🔑 4. Оффлайн-Активация (Air-Gapped)

Активация военного ключа (KAPT / KPT) производится через криптографическую проверку контрольной суммы непосредственно на устройстве без обязательного соединения с серверами.

🛡️ Соответствие уставным нормам: База данных роты никогда не покидает смартфон бойца без прямого ручного подтверждения командира.
