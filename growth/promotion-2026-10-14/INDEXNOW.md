# IndexNow после проверенной публикации

14 октября 2026 года. Ветка содержит исправление существующей интеграции. Производственное уведомление этой задачей не запускалось. [Официальный протокол](https://www.indexnow.org/faq) подтверждает получение URL кодами 200/202; это не гарантия индексации, показов или трафика.

Существующий файл `docs/903fd952854fcb833f54ad87ef4b033b.txt` остаётся публичным подтверждением владения доменом. Это специально опубликованный ключ IndexNow; пароли и приватные токены не нужны. Перед POST проверяется прямой ответ 200 того же хоста и точное содержимое ключа, допускающее один завершающий перевод строки. При отсутствии или несовпадении файла уведомление пропускается.

`site-pages.yml` готовит план до развёртывания: сравнивает только текущие публичные canonical HTML из sitemap и их локальные зависимости с реальным сайтом. HTML, CSS, локальные ES-модули, изображения/og:image/srcset, постеры, видео и шрифты сравниваются по SHA-256. `release.json` учитывается лишь на страницах, действительно выводящих поля `data-release-*`. `version.json`, который только вызывает перезагрузку, в содержимое не включается. Ссылки `<a href>` не распространяют изменения на другие страницы; изменение даты sitemap не отправляет весь список. Чужие хосты, аккаунтные API, страницы noindex/none и неканонические URL исключены. Новый URL определяется по реальному 404; неизвестные 403/500/сеть не считаются изменением. GET не создаёт новую заявку на индексацию.

План сохраняется отдельным Actions artifact вне `docs`. После успешного Pages publish выполняется необязательный job с тем же SHA. Он проверяет ownership и точное совпадение изменившихся страниц и всех выбранных ресурсов с кандидатом на живом сайте. Неизвестный или несовпадающий результат пропускается. Ошибка IndexNow не меняет результат проверок или успешной публикации сайта; существующие CI-пороги сохранены. Старый push workflow выполняет только тесты и не отправляет URL.

Квитанции содержат URL, fingerprint, время UTC, HTTP-статус и SHA. Они сохраняются в существующем Actions cache; тот же журнал сохраняется artifact на 90 дней. Для повторной попытки того же run дополнительно читаются прежние result artifacts. Разрешение повторного POST требует квитанцию **непосредственно предыдущей попытки**: точный cache key и метаданные runId/runAttempt либо соответствующий журнал того же run и SHA. Оба должны подтверждать `receiptHistoryComplete=true`. Старый cache другого запуска или журнал более ранней попытки этого не доказывает: уведомление пропускается. Если история потеряна, признак неполноты сохраняется в последующих квитанциях; пустой журнал безопасного пропуска не разрешает будущий повтор. Уже принятый fingerprint повторно не отправляется. Полный rerun готовит план заново и обнаруживает отсутствие изменений даже при очистке cache.

Максимум 3 попытки отправки при сетевых сбоях, 408, 429 и 5xx; постоянные 4xx не повторяются. Проверка распространения кандидата также ограничена 3 раундами. `Retry-After` соблюдается и для GET, и для POST: если сервер требует ожидать дольше 30 секунд, процесс останавливается без преждевременного повтора. Один GET/POST ограничен 10 секундами, вся подготовка 180 секундами, уведомление 240 секундами. В журнале указаны все статусы, UTC, URL, попытки и причины пропуска; тело ответа сервиса не выполняется и не интерпретируется.

Автоматизация работает в GitHub Actions без включённого ПК, платных посредников, новых аккаунтов и дополнительных token permissions. Сохраняются имеющиеся `contents:read` и права только существующего Pages publish job. Используются квоты существующего GitHub проекта. План и журнал не публикуются как файлы сайта.

Пределы: Actions cache может быть удалён по сроку/квоте; поэтому потерянная история повторной попытки приводит к безопасному пропуску. Если сервис получил POST, но сеть оборвалась до ответа, нельзя доказать отсутствие приёма; ограниченный повтор может повторно передать URL. Ровно однократную доставку протокол без идемпотентной квитанции не гарантирует. Если все попытки неудачны, задним числом успешная доставка не объявляется, а новый полный deploy может уже не иметь новых изменений для этого URL. Постоянный мониторинг индексации и автоматический сбор аналитики этой интеграцией не подключены.

После разрешения владельца объединить PR и запустить существующую ручную публикацию сайта. Затем открыть её `indexnow-plan-<run_id>` и `indexnow-result-<run_id>-<attempt>`: подтвердить конкретные URL, совпадение живых ресурсов, HTTP 200/202 или честные причины пропуска. Успешную индексацию проверять отдельным доступным отчётом поисковой системы. До этого этапа опубликованной считается прежняя версия сайта; новая интеграция остаётся подготовленной и проверенной тестами.
