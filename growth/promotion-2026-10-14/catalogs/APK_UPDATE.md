# Обновления карточки Uptodown

Этот порядок подготовлен 14 октября 2026 года. Единственная карточка 1000901708 остаётся Overall Draft: APK — Pending Review, 3 снимка и обложка — Pending approval, RU/EN описания сохранены под редакционной проверкой. Полная отправка приложения не подтверждена, общие поля не сохраняются. Автоматическая отправка APK не включена. Код, SDK, оплата и исторический сертификат приложения не меняются ради каталога.

Отдельная заявка профиля издателя на https://www.uptodown.dev/organization-edit подтверждена как Pending revision и сохранилась после reload. Пока она обрабатывается, профиль отключён для редактирования и показывает старые значения; это не ошибка его Save. Бренд ещё не опубликован, общий статус приложения остаётся Draft. Возможная зависимость отправки приложения от одобрения профиля — только предположение. После решения по профилю проверить общие поля приложения заново, не создавать второй профиль/черновик и не повторять pending request.

До следующего обновления устранить текущий блокер обычного UI. File UI показывает Max SDK 14 при фактическом Min SDK 24 и отсутствии maxSdkVersion в APK; это расхождение метаданных магазина, а не основание менять APK. Заголовок черновика всё ещё показывает стандартный Android, поэтому сохранение подготовленной брендовой иконки тоже не подтверждено. Сначала проверить сохранение общей информации, повторить обычную загрузку иконки, сверить поля SDK магазина и реальный общий статус карточки.

1. После согласованного выпуска нового официального APK выполнить `node tools/growth/catalog-apk-check.mjs --public`. Сохранить JSON результата в журнал следующего релиза. Скрипт читает APK/манифест, запускает aapt и apksigner и сравнивает байты официального сайта. Он не входит в аккаунты и ничего не отправляет. Для другого SDK есть `--build-tools DIRECTORY`.
2. Продолжать только при `passed: true`. Проверить, что package и SHA-256 исторического сертификата совпадают с прежним выпуском, versionCode выше опубликованного в Uptodown, а номер версии, размер и SHA APK совпадают с `release.json`. При изменении этих условий не ослаблять проверку. Это проверка файла, а не функциональный тест установленного приложения или антивирусное заключение.
3. Обновить краткое и полное описание, changelog, цену и платные возможности, если они фактически изменились. В новой версии не обещать функции только по названию релиза. Если интерфейс изменился, получить его актуальные снимки на вымышленных данных с устройства или production-рендера. Сохранить оригиналы и точное происхождение, сверить показанный код с источниками опубликованного APK; тестовый рендер не объявлять записью физического телефона.
4. В существующей карточке Developers Console выбрать Apps → Edit → Files → Add new version. Использовать проверенный APK или прямую официальную ссылку загрузки. Новую карточку того же package не создавать. Записать ID файла, дату, SHA, versionCode и статус отправки.
5. После Submit for review различать общий статус карточки, статус APK, редакционную проверку описаний и одобрение изображений. Pending Review у файла или Pending approval у изображений не доказывают общую отправку Draft. Только подтверждённый общий Pending означает полную заявку на рассмотрении; Waiting for Publication и Published фиксируются отдельно. Одобрение и срок публикации заранее не гарантировать. При отклонении сохранить конкретную причину и исправлять только разрешённые метаданные; изменения безопасности, SDK, кода, подписи или оплаты согласовать отдельно.
6. После фактической публикации проверить публичную карточку, основную версию загрузки, пакет, подпись и контрольную сумму доступного APK. Скачивание магазина, новый install и update — разные показатели; не суммировать их и не подставлять клики сайта вместо установок.

По [официальной инструкции обновления](https://support.uptodown.com/hc/en-us/articles/360061457991-How-to-update-an-app-that-you-already-published-on-Uptodown) редакторы Uptodown могут самостоятельно получать новые версии из официальных источников, если не включено Disable uploads by Uptodown editors. Это возможность редакции магазина; её срабатывание для Каптёрки пока не подтверждено. Наш автоматический upload API, расписание отправки или гарантированный срок обновления не настроены.

Проверка `catalog-apk-check.mjs` пока запускается вручную и требует среды с Node, Java и Android build-tools. Она ещё не встроена в облачный релизный pipeline. При выключенном ПК вручную выполнить её нельзя. Работа редакторов Uptodown, когда карточка будет опубликована, происходит на стороне магазина и от ПК владельца не зависит.
