# Бесплатное привлечение: результаты для ревью

Дата: 13 октября 2026, Москва. Рабочая ветка `work/free-growth-kit-2026-10`. Подготовлена локальная правка существующего сайта и материалы для внешних площадок. Публикаций, рассылок, платных подключений и новых расписаний не выполнялось.

## Что реализовано

- На существующей странице `uchet-instrumenta-android.html#workshop-kit` — прямые загрузки пустого и примерного XLSX/PDF для кладовой мастерской. Пятая загрузка — печатный лист сверки. Никакой регистрации, подписки или сбора контактов. В материалах ссылка и QR на эту страницу; данные примера вымышленные.
- На `inventarizaciya-na-android.html#reconcile` — локальная сверка учётного и фактического количества, недостача/излишек, CSV. До 100 строк, дроби до трёх знаков. Отрицательные и пустые количества отклоняются; ноль разрешён. Разные единицы не суммируются. Список не сохраняется и не отправляется. Формулы в пользовательских текстах CSV обезвреживаются.
- На существующей странице перемещений — проверяемый пример 20/4 → 14/10 и обратное перемещение 2 пар → 16/8. Общий итог 24.
- Добровольные кнопки «Поделиться пустым шаблоном» и «Посоветовать приложение» вызывают системный Web Share API только с фиксированной публичной ссылкой. При недоступности меню показывается ссылка для ручного копирования. Отправка и доставка не считаются подтверждёнными.
- Главная ведёт к бесплатному комплекту с первого экрана. Условия демо уточнены: 72 часа с первого запуска, PRO 30 суток, лицензия установки, сохранение дней при продлении до окончания и доступ к данным после окончания. Доказательства и ограничения — `product-evidence.md`.
- SHA-256, размер и версия выводятся из одного проверяемого `release.json`: HTML создаётся командой `node .github/scripts/site-release-check.mjs --write`, при просмотре тоже используется манифест. Ошибка хэша, размера, настоящей версии APK или запасного HTML останавливает проверку. Устранён старый SHA на странице безопасности. Галерея честно подписана как примеры интерфейса 3.6, вместо неподтверждённых «настоящих экранов текущего релиза».
- Скрипты главной загружаются с `defer`, четыре CSS собраны без изменения порядка в один файл (197 528 → 159 967 байт), превью галереи WebP 35–40 КБ вместо JPEG 158–196 КБ. Крупные оригиналы доступны в просмотре изображений. Согласованы sitemap и имеющиеся метаданные дат; даты не сбрасывались массово на текущую.
- Повторно используются существующие GA4 и Метрика, добавлены цели скачиваний, расчётов, экспорта и запросов меню. На калькуляторе выключены автоматическая карта кликов и учёт ссылок. События не получают пользовательские поля. Подробная семантика — `MEASUREMENT_AND_EXPERIMENT.md`.

## Что мешает публикации и что требует отдельного решения

1. **Локальный снимок устарел относительно сайта.** Исходники 3.8.0/36, локальный APK/манифест 3.7.0/35, живой манифест 3.8.0/36, web `3.8.0-web.56`. Защита `site-publish-check` действительно выдала STOP. Перед публикацией переносить только этот коммит на свежую `origin/main` в рабочей ветке, сохранив её APK/release.json; заново сгенерировать HTML и выполнить проверки. Нельзя выкладывать целиком текущий `docs/` поверх живого сайта. Защищённые файлы не менялись.
2. **GitHub Pages требует согласованной настройки.** Подготовлен ручной `site-pages.yml`: только main, публикация зависит от целостности, версий, браузерных и Lighthouse-проверок. Для действительной блокировки прежнюю публикацию из ветки надо переключить в Settings → Pages → Source → GitHub Actions. Сейчас эта настройка не менялась, workflow не запускался. Сам по себе обычный push-check не блокирует встроенную публикацию из ветки. Новые права `pages:write`/`id-token:write` ограничены предложенным job и начнут использоваться только после согласованного включения.
3. **Статистика и цели:** нужны агрегированные выгрузки существующих Метрики, Вебмастера и RuStore. Приём новых целей в аккаунтах не проверен. Установки/демо/оплаты не выводятся из кликов, сквозная атрибуция отсутствует.
4. **Карточки, запись и публикация видео:** требуется проверить Консоль RuStore и снять настоящие экраны доступного пользователям релиза на вымышленных данных. Загрузка карточек, публикация роликов и наружных материалов — отдельный этап.
5. **Отдельная sync-задача:** по коду сохранились last-write-wins для абсолютного остатка при одновременной работе двух телефонов и сообщения об успехе до ответа облака. Это подтверждённые риски, не новое испытание воспроизведения. Ядро в маркетинговой работе не переписывалось.

Предлагаемый 30-дневный эксперимент и еженедельный отчёт — в `MEASUREMENT_AND_EXPERIMENT.md`. Расписание предложено, но не включено: понедельник 10:00 МСК, владельцу в этом чате, только агрегаты/ошибки/одно улучшение, без рекламных расходов. Локальная работа требует включённого ПК.
